Problem Statement

The Problem with Modern Cloud DevOps

Modern applications run as dozens of microservices on Kubernetes clusters. Teams make critical infrastructure changes — scaling deployments, rolling updates, node replacements — often without truly knowing the impact in advance.

🔴
Blind Production Changes
A wrong deployment can crash services affecting thousands of users in seconds.
💸
No Cost Visibility
Teams over-provision resources without real-time cost feedback — wasting thousands monthly.
🔧
Existing Tools Are Expensive
Datadog costs $15-40/host/month. New Relic, Dynatrace — all enterprise-priced and complex to set up.
💡 The Solution

A Digital Twin of the Kubernetes cluster — a real-time virtual replica that lets you:

  • Visualize infrastructure as an interactive map
  • Simulate deployment changes safely
  • Track costs before they become a surprise
✅
Built with open-source tools only.
$0 monitoring cost beyond your existing AWS bill.
Concept

What Is a Digital Twin?

The concept is used in aerospace, manufacturing, and healthcare. We apply it to cloud infrastructure.

🏭
Manufacturing
BMW creates digital twins of car factories to simulate production lines and prevent downtime.
🚀
Aerospace
NASA uses digital twins of spacecraft to monitor systems and simulate repairs before executing them.
🏥
Healthcare
Surgeons practice on 3D digital twin organs before performing actual operations.

Platform Capabilities

What TwinDigital Does

🗺️
Live Topology Graph
ReactFlow interactive visualization of the Kubernetes cluster, showing deployments, services, and running pods.
⚙️
Jenkins CI/CD Live Status
Real-time build status, pipeline stages, duration, and success rate queried directly from the Jenkins REST API.
☕
Microservices Architecture
7 Java Spring Boot microservices interacting with a central Node.js API Gateway, all running on Kubernetes.
🔒
DevSecOps Security
Jenkins pipeline integrates GitLeaks, Semgrep (SAST), Checkov (IaC), and Trivy for full Docker/K8s vulnerability scanning.
📊
Prometheus Monitoring
Direct PromQL queries via Node.js fetching CPU, Memory, and Node health metrics from the live K8s cluster.
🔄
Kubernetes Operations
Secure SSH integration allows executing kubectl commands (like restarts or log fetching) directly from the dashboard.
🐳
Docker Hub Registry
Automated building, tagging, and pushing of 7 individual service container images to Docker Hub during CI/CD.
🛠️
Infrastructure as Code
AWS EC2 instances, Security Groups, and Networking provisioned entirely via Terraform with S3 remote state.
👥 Role-Based Access
JWT-secured login with different dashboards for distinct user roles (Admin, DevOps, Viewer).

Architecture Deep Dive

The 7 Microservices

🌐
API Gateway
Acts as the single entry point for all frontend requests, routing traffic to the internal network securely.
🔐
Auth Service
Handles JWT token issuance and strict Role-Based Access Control (Admin vs Viewer).
🔄
Cluster Sync Service
Continuously pulls state from Kubernetes to ensure the Digital Twin is perfectly synced.
🗺️
Topology Service
Parses complex cluster YAML data into structured nodes and edges for the ReactFlow visual map.
🧪
Simulation Service
The sandbox engine. Evaluates proposed scaling or deployment changes before applying them.
⚠️
Risk Service
Analyzes live CPU/RAM metrics against simulated deployments to flag potential crash risks early.
💰
Cost Service
Calculates estimated infrastructure costs based on running pods and simulated capacity.

Data Integration

How Real-Time Data Flows

📡 PROMETHEUS — Real PromQL Queries
avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100
sum(node_memory_MemAvailable_bytes)
sum(kube_pod_status_phase{phase="Running"})
sum(kube_pod_container_status_restarts_total)
sum(ALERTS{alertstate="firing"})
5-second timeout with graceful fallback to store.js if Prometheus is unreachable.
🔁 JENKINS — Live Build API
Queries 65.0.186.162:8080/job/digital-twin-pipeline/api/json using Basic Auth. Returns last 4 builds with status, duration, build number.
🖥️ SSH / kubectl — Cluster Control
Backend SSHes into Master Node (65.2.224.226) and runs kubectl commands:

kubectl rollout restart deployment -n digitaltwin
kubectl logs -n digitaltwin -l app=<service> --tail=100
kubectl get deployments -n digitaltwin -o json
✅ GRACEFUL FALLBACK SYSTEM
Every API response includes a dataSource field:
"prometheus" — Live data
"fallback" — Curated store.js data

The dashboard works even when the cluster is offline.

Lessons Learned

Real Challenges I Solved

Every problem taught a production-level lesson about distributed systems.

Problem Faced
How I Fixed It
🔴 Prometheus metrics all returned 0 or null
✅ Rewrote PromQL from Actuator up{} metrics to node_cpu_seconds_total — correct for Node Exporter
🔴 SSH rejected: "Permission denied (publickey)"
✅ Windows Docker forces 777 permissions on volumes. Built getSafeSshKey() — copies key + chmod 600 on start
🔴 White screen flash when switching dark mode tabs
✅ LoadingSkeleton had hardcoded white background — replaced with MUI sx={{ bgcolor: 'background.default' }}
🔴 Frontend API calls failing in dev (CORS errors)
✅ Vite config.js was returning empty string — fixed to always return /api prefix for proper proxy
🔴 Docker build taking 3+ minutes on every rebuild
✅ Missing .dockerignore — 60MB node_modules sent to Docker daemon. Added .dockerignore, builds now take 25s
🔴 Breadcrumb "TwinDigital" went to /dashboard instead of landing page
✅ Changed route from isPublic: true to noAuth: true so logged-in users can visit landing page
